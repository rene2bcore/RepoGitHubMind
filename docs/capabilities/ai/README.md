# Capability: `ai`

Cada repositorio guardado recibe, en segundo plano, un resumen corto, su propósito, casos de uso, categorías del catálogo, tags, instalación, ventajas, limitaciones y una valoración de madurez y abandono. Se hace una vez por repositorio para todas las cuentas, con el proveedor que diga el entorno, y nunca impide guardar.

> **Dónde está la verdad.** Las reglas viven en [`docs/specs/ai/spec.md`](../../specs/ai/spec.md) y este README no las repite: enlaza a cada una y dice dónde está implementada. Si algo de aquí y la spec no concuerdan, manda la spec. Proveedor, modelo, prompt, coste y fallos, en [`docs/ai-architecture.md`](../../ai-architecture.md).

## Route Handlers

En `apps/web/src/app/api/v1/repositories/`, envueltos en `handle()`. Contrato en [`docs/api/openapi.json`](../../api/openapi.json).

| Método y ruta                              | Entrada                                                                   | Handler                  | Devuelve                                                                                                                                                  | Sesión |
| ------------------------------------------ | ------------------------------------------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| `POST /api/v1/repositories/{id}/analysis`  | `uuidParamSchema`; `analysisRequestSchema`: `force?` (booleano), `strict` | `[id]/analysis/route.ts` | `202 { data: UserRepository }` si queda un análisis en camino; `200` si no hacía falta o la IA está apagada; `404` id ajeno; `422` antes que `404`; `429` | sí     |
| `GET /api/v1/repositories?category=<slug>` | `libraryQuerySchema.category`: slug del catálogo                          | `route.ts` (`GET`)       | La biblioteca filtrada por la rama entera de la categoría; un slug fuera del catálogo es `422` sobre `category`                                           | sí     |

`POST /api/v1/repositories` también pide el análisis, con la misma regla de caché: ver [`capabilities/repositories`](../repositories/README.md).

## Server Actions

Ninguna. «Reintentar» llama a `api.requestAnalysis` desde `components/analysis-status.tsx`.

## Formas de respuesta

`repository.analysis` (`analysisSchema` en `packages/shared/src/schemas.ts`), el mismo en la lista, al guardar y en el detalle:

| Campo                                                                                                                                                                     | Qué                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `status`                                                                                                                                                                  | `PENDING`, `COMPLETED`, `FAILED` o `DISABLED`                                                     |
| `summary`, `purpose`, `mainUseCases`, `installationSummary`, `deploymentType`, `frameworks`, `maturity`, `advantages`, `limitations`, `targetUsers`, `activityAssessment` | Contenido del análisis; vacíos hasta el primer `COMPLETED`. Se conservan mientras se reanaliza    |
| `tags`                                                                                                                                                                    | Tags de IA, con lo que no mapeó al catálogo. Los topics de GitHub siguen en `repository.topics`   |
| `abandonmentRisk`, `abandonmentRiskSource`                                                                                                                                | `LOW`…`UNKNOWN`, y `HEURISTIC` o `AI`. Se calcula al leer: la heurística manda cuando tiene datos |
| `aiAnalyzedAt`                                                                                                                                                            | Fecha del análisis vigente                                                                        |

`repository.categories` es `[{ slug, name, path }]`, ordenado por `path`. La confianza del modelo (`ai_confidence`) no sale.

## Ejecutar y probar

```bash
docker compose -f docker/docker-compose.yml up -d postgres
pnpm test -- packages/ai                 # proveedor con fetch grabado, caché, heurística, mapeo, recorte, registro
pnpm test -- apps/worker/tests/analisis  # el worker contra la base de pruebas con el proveedor falso
pnpm test -- apps/web/tests/analisis     # guardar, segunda cuenta, reintentar, forzar, filtro
pnpm test:e2e                            # web y worker reales con GITHUB_FAKE=1 y AI_FAKE=1
node scripts/mutaciones.mjs ADR-0009
```

En desarrollo sin clave: `AI_FAKE=1` en `.env`, y `pnpm dev` levanta web y worker. Con clave de OpenRouter: `AI_FAKE=0`, `AI_API_KEY` y, si se quiere otro modelo, `AI_MODEL_ANALYSIS`. Coste acumulado por repositorio: la consulta de [`ai-architecture.md`](../../ai-architecture.md) · «Coste».
